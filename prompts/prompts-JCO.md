# Prompts utilizados - JCO

1. "Necesito implementar el ejercicio de QA del modulo 11 del master AI4Devs. El repositorio base es una aplicacion LTI full-stack con frontend React dentro de `/frontend` y backend Express/Prisma. El objetivo del ejercicio es anadir pruebas End-to-End con Playwright para la interfaz `Position`, que muestra un tablero tipo Kanban con columnas por fase del proceso de contratacion y tarjetas de candidatos. Revisa primero la estructura del proyecto, identifica los componentes que renderizan `/positions/:id`, los endpoints que consume la pantalla y el mecanismo de drag and drop usado. No modifiques codigo todavia; entregame un plan de implementacion con los archivos que habria que tocar, riesgos tecnicos y estrategia de pruebas."

2. "Con base en el analisis anterior, configura Playwright dentro de `/frontend` para ejecutar pruebas E2E en Chromium. Anade los scripts necesarios en `package.json`, crea `playwright.config.ts` y configura un `webServer` que levante la app React en `http://127.0.0.1:3000`. La configuracion debe permitir ejecutar `npm run test:e2e` en modo headless y `npm run test:e2e:ui` en modo interactivo. Evita depender de servicios externos reales durante los tests."

3. "Revisa los componentes de la interfaz `Position` y anade selectores estables `data-testid` donde sea necesario para que los tests E2E no dependan de clases CSS, estructura Bootstrap ni texto ambiguo. Necesito poder localizar: la pagina de posicion, el titulo de la posicion, el tablero, cada columna/fase y cada tarjeta de candidato. Mantén los cambios de UI minimos y sin alterar el diseno visual."

4. "Implementa el archivo `/frontend/tests/e2e/position.spec.ts` con Playwright. La prueba debe cubrir el escenario 1: carga de la pagina `Position`. Simula con `page.route` las respuestas de backend para `GET /positions/:id/interviewFlow` y `GET /positions/:id/candidates`, usando datos controlados. Verifica que se muestra el titulo de la posicion, que existen las columnas de fases y que cada candidato aparece en la columna correcta segun su fase actual."

5. "Amplia `/frontend/tests/e2e/position.spec.ts` con el escenario 2: cambio de fase de un candidato. Simula el movimiento por drag and drop de una tarjeta desde una columna de origen hacia otra columna. Verifica tres cosas: que la tarjeta aparece visualmente en la nueva columna, que se dispara una peticion `PUT /candidate/:id` o el endpoint equivalente usado por la UI, y que el body enviado contiene el `applicationId` y la nueva fase/step esperada. Mockea una respuesta exitosa del backend y valida que `response.ok()` sea true."

6. "Ejecuta `npm run build` dentro de `/frontend` y despues `npm run test:e2e`. Si falla la compilacion o falla Playwright, diagnostica la causa usando los logs, corrige solo lo necesario y vuelve a ejecutar hasta que el build y los tests E2E queden verdes. No ocultes errores reales ni relajes las aserciones para que pasen sin validar comportamiento."

7. "Revisa el diff final como si fueras reviewer senior de QA. Comprueba que los cambios cumplen la consigna: configuracion de Playwright, archivo `position.spec.ts`, validacion de carga visual, validacion de drag and drop, verificacion del `PUT`, selectores estables y archivo de prompts. Asegurate de que no quedan artefactos generados como `test-results`, `playwright-report`, `build` o `node_modules` preparados para commit. Dame tambien el resumen de comandos ejecutados y el resultado final de las pruebas."
